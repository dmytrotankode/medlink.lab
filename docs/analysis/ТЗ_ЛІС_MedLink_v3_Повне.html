1. Паспорт проєкту та продуктове позиціонування

Проєкт MedLink LIS 3.0 покликаний реалізувати сучасну, високоавтоматизовану, клінічно достовірну лабораторну інформаційну систему з відкритою інтеграційною шиною, що вирішує подвійне бізнес-завдання:

1. Вбудований лабораторний контур MedLink

Безшовна частина діючої медичної інформаційної системи evomis. Закриває повний діагностичний цикл для лікарень та приватних клінік: лікар у картці створює призначення або електронне направлення ЕСОЗ → лаборант у пункті забору маркує пробірку → аналізатор видає результат → лікар-лаборант валідує → дані автоматично повертаються в ЕМК пацієнта та гасяться в eHealth (DiagnosticReport) з КЕП.

2. Standalone LIS (Самостійний продукт)

Автономна LIS корпоративного рівня для комерційних лабораторних мереж, пунктів забору та приватних кабінетів, що не використовують МІС MedLink. Включає власний білінг, склад реагентів, логістику зразків, модуль внутрішнього контролю якості (ВЯК) за Вестгардом та інтеграцію із зовнішніми МІС через HL7 v2 / FHIR / REST API.

Ключова перевага MedLink LIS: Повна ліквідація десктопного легасі-коду (Delphi). Перехід на 100% хмарну архітектуру (Web/PWA на Quasar) з кросплатформним системним демоном зв'язку з приладами на .NET Core (Windows Service / Linux systemd daemon), що забезпечує безвідмовний обмін з приладами без прив'язки до робочого місця оператора.

2. Аналіз конкурентів, матеріалів MCLAB/TerraLab та аудит Delphi

В ході ретельного аудиту проаналізовано 4 ключові джерела: legacy-код Delphi (C:\Desktop\src, база hospital_etalon, плагін AConnect), систему LIMS TerraLab Pro, документацію MCLAB (папка C:\__MEDLINK___\Лаборатория\MCLAB) та функціонал промислових LIS (STARLIS, LISmart):

Компонент / Система Legacy Delphi (AConnect / hospital_etalon) Конкуренти (TerraLab, MCLAB, LISmart) Рішення MedLink LIS 3.0 (.NET 6 / Web)
Архітектура зв'язку з приладами Delphi VCL застосунок (AConnectAstm.exe), прив'язаний до COM/TCP. Монолітний розбір в SQL процедурі parse_lab_message (142 КБ коду з блокуваннями таблиць). Окремі десктопні драйвери під кожен прилад, часті падіння при перезавантаженні ПК, відсутність буферизації. MedLink.LabConnector: фоновий worker на .NET Core (Windows Service + Linux systemd). Локальний SQLite offline-буфер. Асинхронний розбір ASTM E1381/E1394 та HL7 MLLP на рівні коду C# з відправкою JSON через HTTPS REST API.
Контроль якості (QC / ВЯК) Повністю відсутній у коді Delphi та базі даних. У TerraLab/STARLIS є графіки Леві-Дженнінгса та правила Вестгарда, але жорстко прив'язані до десктопу, без автоматичного блокування видачі пацієнтських результатів. Повноцінний веб-модуль ВЯК: 3 рівні контролів (Low/Normal/High), мультивідхилення Вестгарда (1-2s, 1-3s, 2-2s, R-4s, 4-1s, 10-x), автоматичний Lockout (блокування валідації пацієнтських тестів при порушенні), інтерактивні карти Леві-Дженнінгса.
Пункт забору & Маркування Базовий друк штрихкодів через генератор gen_lab_tube_barcode (EAN-8/128). Немає контролю черговості пробірок (Order of Draw). В MCLAB є окремі інструкції («Додавання біоматеріалу та друк етикеток.pdf»). Підтримка термопринтерів. Інтелектуальний кабінет забору: автогрупування тестів у пробірки за типами біоматеріалу, обов'язковий порядок набору за CLSI (культури → цитрат → сироватка → гепарин → ЕДТА → фторид), прямий друк на Zebra/TSC через ZPL/TSPL.
Логістика & Температурний ланцюг Відсутня логістика в Delphi. У TerraLab є маршрутні листи кур'єра, але без фіксації температури в точках передачі. Модуль логістики зразків: електронні акти прийому-передачі (термосумки), валідація холодового ланцюга (t° відправки та прибуття), мобільний інтерфейс кур'єра зі скануванням штрихкодів сумок.
Кабінет пацієнта & Моніторинг Відсутній. Більшість LIS не мають пацієнтського кабінету, віддаючи результати тільки PDF-файлом на email. Live-трекер для пацієнта: інтерактивний таймлайн виконання (Забір → В дорозі → Доставлено → В аналізі → Готово), графіки персональної динаміки показників, завантаження бланка з захисним QR-кодом автентифікації.

QC-01 Автоверифікація результатів (Rule Engine) Клінічна якість Автоматичне закриття результату, якщо: значення суворо в межах норми, відсутні прапорці приладу, delta-check у нормі, тест не вимагає обов'язкового ручного перегляду. Must R1 (MVP)
QC-02 Delta-Check (Порівняння з анамнезом) Клінічна якість Порівняння поточного показника з попереднім результатом пацієнта за вікно 72 год. При стрибку понад заданий % (напр. >25% для креатиніну) — блокування автовидачі. Must R1 (MVP)
QC-03 Reflex-тестування (Автодопризначення) Клінічна якість Алгоритмічні ланцюжки: якщо ТТГ патологічний → автододавання вТ4; якщо позитивний скринінг гепатиту → автопризначення підтверджуючого блоту. Should R2
QC-04 Маршрутизація критичних значень (Panic Values) Клінічна якість При виявленні загрозливих значень (глюкоза <2.5 або >25 ммоль/л, калій >6.5): миттєвий екранний алерт, push-сповіщення лікарю з вимогою підтвердити ознайомлення. Must R1 (MVP)
QC-05 Довідник контрольних матеріалів & Серії Клінічна якість Облік контрольних сироваток (Level 1, 2, 3), номери партій, терміни придатності, стабільність відкритого флакона, паспортні середні та SD від виробника. Must R1 (MVP)

Пункт забору біоматеріалу (як при стаціонарі/поліклініці, так і віддалене відділення) є критичною точкою преаналітичного етапу, де виникає до 70% усіх діагностичних помилок. Модуль MedLink LIS проектується для максимального захисту від людського фактору:

Клінічний чек-лист взяття біоматеріалу

  • Ідентифікація пацієнта: двофакторне підтвердження (ПІБ + дата народження або номер карти).
  • Верифікація підготовки: фіксація статусу (натщесерце / не натщесерце, прийом антикоагулянтів/гормонів).
  • Анатомічна локалізація: вибір вени (ліктьова права/ліва, тил кисті, капілярний забір).
  • Фіксація часу: точний системний таймштамп пункції з прив'язкою до ідентифікатора медсестри.

5. Логістика біоматеріалу, холодовий ланцюг та лабораторний бракераж

🚚 Відкрити прототип Логістики та бракеражу →

Для мереж лабораторій або лікарень із відокремленими корпусами транспортування зразків регламентується модулем логістики:

1. Електронний маніфест передачі

Партія пробірок сканується в термосумку. Формується Акт прийому-передачі з QR-кодом контейнера. Кур'єр підтверджує прийом в один клік у веб-інтерфейсі смартфону.

2. Контроль холодового ланцюга

Обов'язкова фіксація температури за термодатчиком: при виїзді з пункту забору (+4°C) та при прибутті в лабораторію (+5°C). При відхиленні понад +8°C система маркує рейс як інцидент.

3. Стіл акцепту та бракеражу

Оператор приймального відділення сканує пробірку. При виявленні преаналітичного дефекту вказується статус браку з автоматичним сповіщенням на повторний забір.

Тип браку зразка Клінічний вплив на аналіз Дія системи MedLink LIS
Гемоліз (+, ++, +++) Штучне завищення Калію (K+), ЛДГ, АСТ, АЛТ, заліза через руйнування еритроцитів. Блокування аналізу біохімічних тестів, автоматичне завдання медсестрі на перезабір, повідомлення лікарю.
Хілоз / Ліпемія Каламутність сироватки спотворює оптичну фотометрію та нефелометрію. Рекомендація повторного забору після 12-годинного голодування.
Наявність мікрозгустків Забиває капілярну гідравліку гематологічного аналізатора, спотворює тромбоцити. Категорична відмова в аналізі ЗАК/коагулограми.
Недостатній об'єм (Underfilling) Порушує співвідношення кров/антикоагулянт (особливо для цитрату 1:9). Анулювання направлення на коагулограму (непридатний результат МНВ/АЧТЧ).

8. Драйверний коннектор MedLink.LabConnector (.NET Core Worker)

Драйверний коннектор MedLink.LabConnector — це високопродуктивний кросплатформний фоновий сервіс, розроблений компанією MedLink на платформі .NET 6 / .NET 8 Worker Service. Він повністю замінює застарілу 32-бітну програму на Delphi (AConnectAstm.exe) та забезпечує роботу як у середовищі Windows (Windows Service / Tray), так і в Linux (systemd daemon для шлюзів на базі Ubuntu/Debian або Raspberry Pi / компактних контролерів біля приладів).

Правовий статус та інтелектуальна власність: Всі майнові та авторські права на вихідний код, протокольні парсери (ASTM, HL7, MLLP), схеми буферизації та інсталятори коннектора належать виключно ТОВ «МедЛінк» (MedLink LLC). Ліцензійна угода (EULA) та підпис цифровим сертифікатом фіксують авторство MedLink.

Архітектурні особливості коннектора

  • Асинхронний мультиплексинг: Один екземпляр коннектора одночасно обслуговує до 32 лабораторних приладів без взаємних затримок (Task-based asynchronous I/O).
  • Підтримка інтерфейсів: Serial RS-232 (COM-порти через перехідники USB-to-COM або MOXA), TCP/IP Client/Server (порт 1000–9999), спільні файлові каталоги (Folder Watcher).
  • Локальний SQLite буфер: При зникненні Інтернету дані аналізів надійно зберігаються на диску ПК біля приладу та скидаються в хмару MedLink автоматично після відновлення зв'язку.
  • Відкритий REST API обміну: Коннектор спілкується з хмарним ядром MedLink через захищений HTTPS REST API з авторизацією за токеном клініки X-MedLink-ApiKey.

Підтримувані протоколи обміну

  • ASTM E1381 / E1394: Стандарт де-факто для аналізаторів. Повний цикл: кадр ENQ → ACK → STX [Data] ETX [CRC] → EOT. Двосторонній запит рознарядки за штрихкодом (Query mode).
  • HL7 v2.3.1 / v2.5 MLLP: Сучасний медичний стандарт: сегменти MSH, PID, OBR, OBX, квитування MSA|AA.
  • HL7 FHIR R4: Передача сутностей Observation та DiagnosticReport.
  • File Drop / Polling: Авторозбір CSV, XML та форматованого тексту з мережевих папок.

9. Інтероперабельність: eHealth (ЕСОЗ), HL7 v2, FHIR R4 та Аутсорс

MedLink LIS спроектовано для безшовної роботи в розподіленій медичній екосистемі України та міжнародних стандартів:

1. eHealth / ЕСОЗ (НСЗУ)

Повна інтеграція з центральною базою даних eHealth. Погашення електронного направлення пацієнта (Service Request). Підпис фінального висновку кваліфікованим електронним підписом (КЕП лікаря-лаборанта) та публікація ресурсу DiagnosticReport з прив'язкою до візиту.

2. HL7 FHIR REST API

Сучасний RESTful інтерфейс обміну за стандартом FHIR R4. Дозволяє стороннім клінікам та системам направляти замовлення (ServiceRequest) та отримувати структуровані результати (DiagnosticReport & Observation з кодами LOINC).

3. Зовнішні лабораторії (Send-Out)

Автоматизоване направлення рідкісних або високовартісних аналізів (генетика, рідкісні онкомаркери) до лабораторій-партнерів (Сінево, Діла, CSD, TerraLab) із відстеженням статусу та автоімпортом результату.

// App.Api/Hubs/LabHub.cs
public class LabHub : Hub
{
    public async Task SendAnalyzerResult(string analyzerCode, LabResultDto result)
    {
        await Clients.Group($"Analyzer_{analyzerCode}").SendAsync("ResultReceived", result);
        if (result.IsPanicValue)
        {
            await Clients.Group("Physicians").SendAsync("PanicAlert", result);
        }
    }
}

13. GAP-аналіз: Що було упущено в старих ТЗ та як це вирішено

На основі детального аналізу предметної області та зіставлення legacy-коду Delphi, LISmart, STARLIS і MCLAB виявлено та усунуто 10 критичних прогалин:

№ Упущений аспект у старих версіях Клінічний або операційний ризик Рішення, впроваджене в MedLink LIS 3.0
1 Порядок забору (Order of Draw) Перенесення ЕДТА в цитратну пробірку спотворює час згортання та руйнує аналіз гемостазу. Вбудовано візуальну діаграму та обов'язкову черговість забору за стандартом CLSI H3-A6 у Кабінеті забору.
2 Холодовий ланцюг у логістиці Перегрів зразків у дорозі призводить до лізису клітин та деградації глюкози і ферментів. Обов'язкова валідація температури термосумки (+2...+8°C) при відправці та прийомі в електронному акті.
3 Pre-analytical Бракераж Виконання аналізу на гемолізованій або згущеній крові видає хибні результати пацієнту. Спеціалізований інтерфейс приймального столу з фіксацією гемолізу, ліпемії та автонаправленням на перезабір.
4 Блокування приладу (QC Lockout) При виході контролю якості з ладу лаборант міг випадково валідувати пацієнтські проби. Автоматичний Lockout: порушення правил Вестгарда 1-3s, 2-2s блокує вихід пацієнтських тестів цього приладу.
5 Миттєвий алерт панічних значень Лікар дізнається про смертельно небезпечну глюкозу (26 ммоль/л) лише після планового друку. Push/SMS сповіщення в МІС з вимогою обов'язкового клінічного підтвердження протягом 15 хвилин.
6 Delta-Check за вікном 72 години Пропуск підміни пробірки або раптового гострого погіршення стану нирок (креатинін). Автоматичний розрахунок дельти у % та мг/дл щодо попереднього дослідження пацієнта за останні 72 години.
7 Reflex-правила без зайвих візитів Пацієнт змушений чекати дні та повторно стояти в черзі, якщо виявлено патологію ТТГ. Автоматичне допризначення зв'язаних тестів (вТ4, антитіла) з тієї ж пробірки за затвердженим протоколом.
8 Офлайн-стійкість коннектора При збої Інтернету прилади видавали помилку переповнення буфера (Buffer Overflow). Локальна база SQLite на рівні служби MedLink.LabConnector зі збереженням та фоновим ретраєм.
9 Live-моніторинг для пацієнта Сотні дзвінків у реєстратуру з питанням «чи готові мої аналізи?». Публічний віджет-трекер у кабінеті пацієнта зі статусами «В дорозі», «В аналізі», «Готово».
10 Фізичний архів (Біобанк) Неможливість знайти пробірку пацієнта через 2 дні для додаткового тестування або перепровірки. Координатний облік пробірок у віртуальних штативах (Холодильник → Полиця → Штатив → Комірка [X, Y]).
