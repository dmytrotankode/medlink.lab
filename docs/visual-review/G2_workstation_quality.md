## Наскрізні проблеми

1. Сирі серверні помилки показуються користувачу: .NET-валідація англійською, коди ролей (LAB_ADMIN, LAB_DOCTOR, LAB_TECHNICIAN), enum-статуси (NEW, RECEIVED, ISOLATED тощо). Потрібен єдиний перекладач помилок у boot/axios.js (за кодом і полем) і заборона виводу тексту помилки сервера як є.
2. Права ролей перевіряються лише на сервері: кнопки не приховані й не вимкнені, користувач бачить помилку після кліку. Потрібне приховування або вимкнення дії за роллю з підказкою, чому вона недоступна.
3. Розбіжності назв полів фронт/бек (реагенти, антибіограма) дають «мовчазні» збої: збереження падає або проходить, а таблиця порожня.
4. Англіцизми й жаргон у заголовках та підзаголовках (batch, heartbeat, delta-check, Waterfall, Lockout, CITO, TAT, SLA, P90) — потрібен єдиний словник термінів.
5. Технічні ідентифікатори (GUID, orderTestId) і назва сторонньої системи видно в інтерфейсі — прибрати.
6. Persistent-вікна не закриваються по Esc, поведінка різна на різних екранах.

## Покриття

Екрани (маршрути): Робочий стіл лаборанта; Робота за направленнями (вкладки «Пацієнти» й «Дослідження» переглянуто лише частково); Валідація й критичні значення; Контроль якості; Аналізатори і конектори; Імпорт результатів; Мікробіологія (список і картка культури); Біобанк; Реагенти; Норми (каталог і пісочниця резолвера); Аналітика TAT; Звіти лабораторії.

Вікна: результат, верифікація, дзвінок за критичним значенням, батч, контрольний матеріал, форма аналізатора, культура з антибіограмою, шар норм, лот реагенту та інші діалоги цих екранів.

Сценарії: усі g2-сценарії з Seed/lab_analytics_quality.json (близько 85) звірено з кодом і текстами екранів. У реальному інтерфейсі під відповідною роллю виконано наскрізно: введення результату, створення контрольного матеріалу, створення лота реагенту, культура з антибіограмою, імпорт результатів, виклик за критичним значенням. Для валідації та робочого столу виконано перевірку якорів у живому DOM (усі знайдено, крім елементів, що з’являються лише на інших вкладках або після вибору рядка).

## Що не перевірено

- Розмір 1920×1080 і вузький екран: перевірено лише вікно приблизно 1646×791, окремої перевірки адаптивності немає.
- Вкладки «Пацієнти» й «Дослідження» сторінки «Робота за направленнями» — частково.
- Не відкривалися: вікно точки контролю, розв’язання блокування, списання реагенту, симулятор повідомлень, створення конектора, картка послуги — оцінка лише за кодом.
- Рольова матриця перевірена вибірково (admin, лаборант, лікар, реєстратор), не для кожної дії.
- Частина сценаріїв оцінена лише за кодом і текстами, без наскрізного запуску.
- Шість цитат із кроків сценаріїв не знайдено у вихідних текстах — потребують ручної звірки.

## Що перевірити на стенді

1. Результат для замовлення «Нове» (кнопки неактивні, підказка) і для прийнятого (введення, зберігання).
2. Створення лота реагенту й таблиця залишків; біобанк: штатив → розміщення зразка → біоматеріал у комірці.
3. Посів: створення через вибір дослідження, ізолят, антибіотикограма (S/I/R), переходи статусів під ролями «Лаборант» і «Лікар-лаборант».
4. Імпорт: перевірка → підтвердження → підсумок; звіт ВКЯ; аналітика термінів виконання (лічильники й діаграма).
5. Запуск Guide-сценаріїв `lab.tat.*`, `lab.mb.*`, `lab.ws.select-multiple`, `lab.ws.batch` (якорі).
6. Збірка API (`dotnet build`) — C#-зміни не компілювались.
