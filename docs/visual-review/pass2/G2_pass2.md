# G2 — повторний прохід після виправлень (стенд /lab/, 09.11.2026)

Метод: Chrome, ролі лікар-лаборант, лаборант, кур'єр (адмін і медсестра — лише побічно: роль у localStorage спільна з іншими агентами й перезаписувалась, тому роль перемикалась у пам'яті сторінки через перемикач у шапці). Дані фіктивні; створено й частково прибрано тестові записи (лот RG-TEST-2 видалено; результат WBC 5,5 для 2611-000027 введено й верифіковано; антибіотик Амікацин S для посіву f5a5f4d5; зразок 10048306 у біобанку A-05; імпорт 1 рядка PT=12,5 для 10048290). Консоль: помилок немає. Мережа: усі запити 200, 4xx/5xx не було.

Пройдені сценарії наскрізно: введення результату → верифікація лікарем → (журнал історії); лот реагенту (створення, списання-діалог, видалення); посів → антибіотикограма (помилка валідації, ручна інтерпретація S, таблиця); біобанк (паспорт, розміщення, вилучення-діалог); імпорт (перевірка → підтвердження → підсумок); звіт ВКЯ; аналітика термінів; симулятор аналізатора; журнал обміну; норми (каталог + підбір норми); звіти (Навантаження аналізаторів); робота за направленнями.

## 3. Відхилено скептиком

- Спочатку здавалося, що Esc не закриває вікно «Новий контрольний матеріал» і «Реєстрація дзвінка» — відхилено: при фокусі в діалозі (як у реального користувача) Esc закриває; хибне спостереження через програмне відкриття без фокусу.
- Підозра, що таблиця черги прихована фільтром/display:none для стовпців «Результат/Норма» — відхилено: стовпці присутні (display: table-cell), вони лише поза видимою зоною → записано як С5.
- Підозра на дубль записів історії («Верифіковано» і «Введено» версія 1) — відхилено: це різні події однієї версії.
- Підозра на 4xx/5xx у мережі та помилки консолі — відхилено: усі запити 200, консоль чиста.
- Лишено як обмеження: адмін-роль і вікно коннектора (№ 6), вузька ширина 1024 px, 1920×1080 не перевірялись; сервер для № 97/100 — імовірно не розгорнуто останню збірку.

## 4. Виправлено у третьому заході

Перевірено статично (компіляція шаблонів і синтаксис скриптів); збірку, dotnet-тести й стенд не запускали.

Сервер:
- №97 (причина): у запит звіту ВКЯ і звіту «Навантаження аналізаторів» поле «До» приходить датою без часу (північ), тому блокування, розпочаті в той самий день, відсікались. Тепер «До» без часу означає кінець доби (QcService.ReportAsync, WorkReportsService.BuildAsync). Години блокування рахуються в межах періоду; заблокований прилад без тестів у вибірці тепер теж є рядком звіту. Тест: Reports_with_date_only_period_include_todays_lockouts_and_blocked_analyzer_without_tests.
- №100 (причина): прийом пакета результатів оновлював «Останнє повідомлення» приладу, але не писав запис у журнал обміну. Тепер, якщо коннектор не надіслав окремого запису за останні 2 хв, журнал отримує вхідний запис «Прийнято результатів: N» (ConnectorService.AcceptResultsAsync). Тест: перевірка журналу в наскрізному сценарії коннектора. Зауваження: старі «Останні повідомлення» без записів (дані стенда) журнал не відновить.
- С1: без попереднього результату дельта не зберігається (ResultPipelineService); на екранах Δ% і банер «Різка зміна» показуються лише за наявного попереднього значення (інакше «—»).
- С6: причини блокування автоверифікації без кодів («Результат поза нормою (нижче/вище)», «Різка зміна відносно попереднього результату», «Аналізатор заблоковано контролем якості»), у повідомленні причини згортаються з лічильником.
- Н9: підсумок за напрямками повертає lockoutNames («Назва (код)», «усі показники»); плитка використовує їх.
- Н5/№104: єдина назва «Аналітика термінів виконання» (меню, маршрут, заголовок), «Терміни виконання сьогодні», «Медіана терміну виконання», колонка звіту «Термін виконання (медіана), хв».
