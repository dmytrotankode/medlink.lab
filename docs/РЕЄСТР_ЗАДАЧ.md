## 1. Що саме попросив замовник

### 1.1. Пряма вказівка (переклад з російської, з чату з власником продукту)

> «Зробити повний робочий застосунок у стилі MedLink на основі вимог, які нам дали, + усе, що ми додатково придумали, + робота з референтними нормами з програми Simplex (Delphi-застосунок) + робота коннектора аналізаторів (потрібен повний інсталятор для завантаження та налаштування зв'язку з основною програмою) + усе інше, що потрібно (подивіться на нашу роботу і продумайте, що потрібно)».

### 1.2. Уточнення власника

1. **Технології точно як у MedLink**: .NET 8 Web API + EF Core; Quasar v1.15.3 + Vue 2 (T-009).
2. **Посилання на сутності MedLink**: `mis_patient_card`, `org_employee`, `org_department`, `ehe_incoming_medical_referral`, `mis_diagnostic_report`, `mis_specimen`, `dct_service` (T-010).
3. **Без авторизації користувачів у цьому модулі** — її надає evomis (T-011). Наслідок: модуль 1 документа v2 «Автентифікація» та PT-01 «Автентифікація пацієнта» делеговані evomis.
4. **SQLite** як БД етапу v4, схема спроєктована для легкого перенесення у реальний проєкт (T-012).

## 2. Правила ведення реєстру

- `T-nnn` — стабільний ідентифікатор; нові задачі додаються в кінець відповідної групи, видалення заборонене (лише статус «Скасовано» з причиною).
- Колонка «Статус у v4»: **Реалізовано** — повністю входить до обсягу v4 за контрактом API; **Частково** — у v4 є структура даних / заглушка / спрощений варіант; **Заплановано** — R2/R3 або зона відповідальності evomis.
- Пріоритет — MoSCoW за документом v2; стрілка «→» означає зміну, узгоджену з власником (напр. «Must→evomis»).
- Зміни реєстру вносяться синхронно у цей файл та розд. 2 ТЗ v4.
