# MedLink Guide SDK — інтерактивні покрокові інструкції (плагін до будь-якої веб-системи)

Фронтенд-частина модуля. Бекенд: `src/MedLink.Guide` (API `/api/v1/guide`), БД: `db/postgres/guide/001_guide_schema.sql` (схема `guide`, таблиці `gd_*`).

Без залежностей (чистий ES2017, UI у Shadow DOM — стилі системи не заважають). Працює у ЛІС (Quasar/Vue 2), evomis та будь-якій іншій системі.

## Підключення

```js
import MedLinkGuide from '<шлях>/MedLink.Guide.Web/src/index.js';

const guide = MedLinkGuide.init({
  appCode: 'lab',                     // ключ системи у БД (gd_app.code)
  appCaption: 'MedLink LIS',
  apiBase: '/api/v1/guide',
  headers: () => ({ 'X-MedLink-Employee-Id': employeeId, 'X-MedLink-Roles': role }),
  navigate: route => router.push(route),          // як відкрити екран у вашій системі (за замовчуванням location.assign)
  currentRoute: () => router.currentRoute.fullPath,
  getRole: () => role,                            // фільтр інструкцій за ролями
  canEdit: () => isImplementer,                   // показувати кнопку «Конструктор»
  button: { mount: document.getElementById('slot') } // або true (плаваюча «?»), false (без кнопки)
  // transcribe: async (blob, lang) => text      // необов'язково: серверне розпізнавання мови замість Web Speech API
});
guide.open();            // панель з деревом інструкцій
guide.start(scenarioId); // запуск з будь-якого місця; плеєр сам переходить на потрібний екран
guide.openBuilder();     // конструктор
```

Демо без сервера: `memory: true` у `init` (дані у localStorage). Демо з реальним API: `dotnet run --project src/MedLink.Guide.DemoHost` → http://localhost:5066.

## Як працює

**Якір** — не один селектор, а набір стратегій за вагою: `data-guide-id` › `data-testid/test/cy/qa` › стабільний `id` › `aria-label`/`name`/`placeholder` › текст › css-шлях від найближчого предка з тест-id. Динамічні значення (Quasar `q-*`, uid, GUID) ігноруються. Додатково зберігається **відбиток** (тег, текст, атрибути, підпис, предки, положення). Якщо жодна стратегія не спрацювала — **нечіткий пошук** за відбитком; знайдене так позначається `healed`, плеєр надсилає звіт `POST /anchor-reports`, автор бачить пропозицію виправлення (`GET /apps/{app}/anchors/health`, `accept`).

**Плеєр**: стан у `sessionStorage` (переживає навігацію/перезавантаження SPA), автоперехід на `step.route`, очікування появи елемента, підсвічування (spotlight) елемента / батьківського блоку (`parentLevels`) / власної зони (`rect`), підказка з «Назад/Далі/Зроби за мене», режим **демо** (сам виконує дії), змінні `{{patient}}` для тестових даних (фіксовані, випадкові, дата, зі списку), `inputMode`: показати / автозаповнити / вимагати ввести. Крок завершується за `expect`: кнопка, клік, введення, зміна, перехід на екран, зникнення елемента.

**Конструктор** (для впроваджувача):
- 🎯 *Вибрати елемент* — наведення курсора, **↑/↓ або панель-ланцюжок зверху** обирають батьківський блок для підсвічування, клік — вибір, Ctrl+клік — виконати дію як зазвичай, Esc — скасувати;
- ⏺ *Записати дії* — кліки та введення в системі автоматично стають кроками (паролі не записуються);
- текст пояснення з 🎤 *диктовкою* (Web Speech API, укр/рус/eng; у Chrome/Edge) або власним `transcribe`;
- зона підсвічування (✏ намалювати), тестові дані та змінні, перевірка якоря («👁 Показати елемент»), порядок кроків, ▶ перегляд чернетки з вибраного кроку;
- 💾 чернетка → 🚀 публікація (знімок версії; користувачі проходять лише опубліковану версію).

## Вимоги до сумісності
Файли написані без `?.`/`??` і class fields, щоб проходити webpack 4 (Quasar CLI v1) без транспіляції node_modules. Стабільні якорі: ставте `data-testid` (у `q-input` він потрапляє на нативний `input`) або `data-guide-id`.
